CASE STUDY 01 · Healthcare integration

A radiology order should reach the right patient

An interrupted connection or a repeated order can leave teams uncertain about what was received. A patient or accession mismatch needs to be visible before any association is accepted.

My contribution

I shaped this portfolio exercise around a business problem, explicit acceptance rules and reviewable exceptions. The implementation and documentation were developed with AI assistance. It demonstrates an approach; it is not a record of a former employer's delivery.

The approach

The lab separates message validation, identity checks and delivery state. It uses a small, explicit subset of HL7 v2.5 ORM^O01 messages so the rules can be inspected and tested.

Decisions and tradeoffs

Treat a repeated message as the same event

Idempotency prevents a retry from creating a second order.

Keep identity conflicts visible

Conflicting patient or accession identifiers need a review path rather than a silent overwrite.

Make interruption recovery explicit

An offline queue and retry action let a reviewer inspect delivery state.

What you can inspect

What this demonstrates

A working example with explicit rules and repeatable checks. No client outcome, cost saving or production performance claim is inferred from this exercise.

Moving toward a real implementation

For a real engagement: agree message profiles and identifier ownership, use approved synthetic test messages, define reconciliation and monitoring, and obtain clinical, security and operational sign-off.

Scope and limits

This is an independent browser demonstration with fictional data. It is not a full HL7 conformance engine, MLLP listener, DICOM server or clinical system. Study association uses metadata, not image transfer.

Resumen en español

Este caso muestra cómo revisar órdenes de radiología, detectar duplicados y hacer visibles los conflictos de identidad. La demo usa datos ficticios y no se conecta a sistemas clínicos.
